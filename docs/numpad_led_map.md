# 小键盘 17 颗 RGB 实际串联顺序

来自用户已上传的立创 EDA Pro 文件：
`ProDoc_键盘87_小键盘_2026-11-03(1).epro`。
用 `PCB/0f93978a359ba176302696e1f0a5a380.epcb` 的 `PAD_NET` 数据追踪 **每个组合按键器件 L2(DIN) / L4(DOUT)**，从网络 `DIN` 开始逐个跟随至网络 `DOUT`，而非按照键盘行列顺序猜测。

| 相对 LED 序号 | 物理位置/标签 | 网络路径 |
|---:|---|---|
| 0 | Num Lock | DIN → U1 L4 |
| 1 | / | U1 L4 → U44 L4 |
| 2 | * | U44 L4 → U71 L4 |
| 3 | − | U71 L4 → DA0 |
| 4 | 7 | DA0 → U2 L4 |
| 5 | 8 | U2 L4 → U51 L4 |
| 6 | 9 | U51 L4 → U73 L4 |
| 7 | + | U73 L4 → DA1 |
| 8 | 4 | DA1 → U56 L4 |
| 9 | 5 | U56 L4 → U57 L4 |
| 10 | 6 | U57 L4 → U68 L2 |
| 11 | Enter | U68 L2 → DA2 |
| 12 | 1 | DA2 → U62 L4 |
| 13 | 2 | U62 L4 → U63 L4 |
| 14 | 3 | U63 L4 → U66 L4 |
| 15 | . | U66 L4 → U3 L2 |
| 16 | U3 额外底排灯（数字 0 位置） | U3 L2 → DOUT |

**合计：17 颗 LED。** 注意 U3 组合器件 LED 在光链中，但其 KEY1/KEY2 开关没有加入现有 MCP23008 的 4×4 扫描矩阵，因此不能因为按键只映射了 16 颗，就只发 16 颗 LED 数据。

## 与原有 100 颗灯的关系

STM32 固件当前 `LED6028_COUNT=100`，主键盘空间坐标的灯索引是 `0..70`。如果小键盘的 `DIN` **实物接在主键盘第 71 颗的 DOUT 后**，那么相对小键盘 LED `0..16` 对应绝对灯号 `71..87`。

但 **PCB 工程仅能证明小键盘自身的链路顺序，无法证明它与主键盘实际插线后的绝对起始号**。所以 KeyFlux GUI 提供可调整的起始序号（默认 71），支持单灯点击与上/下一颗测试，不需要刷机即可核对序号。

若小键盘接在物理灯号 99 之后、独立控制 GPIO 上，或未接入目前 PB6 控制的 LED 数据链，则现有 `0..99` 的固件单灯命令不能直接点亮，需要针对实际连接方案扩展固件。

## KeyFlux 使用

1. 切换 MultiPad，连接键盘 USB。
2. 在「数字小键盘 RGB · 实物单灯测试」中设置起始编号（默认 71）。
3. 点击 **Num**，应只亮第一颗灯；继续点击 `/`、`*`、`-`，直到最后的 **0***。
4. 如果亮灯整体偏移，调整起始编号并继续验证。KeyFlux 会在 PC 上保存起始号。
5. 完成后点击「停止测试」恢复原灯效。

此测试只使用固件已有的 `0x07` 单灯命令；不会改键盘 RGB 存储设置，也不会主动写 STM32 Flash。
